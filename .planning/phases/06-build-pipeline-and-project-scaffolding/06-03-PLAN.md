<objective>
Create the template subsystem — a single `internal/templates` package that embeds all template
files with `//go:embed` and exposes a `Render(name, data)` helper — and author the app-repo build
templates it will serve: the T3/Next standalone Dockerfile and the health-route handler (App and
Pages Router variants). Golden-file tests lock the rendered output.

Purpose: This is the shared rendering seam every later plan builds on. Plan 06-04 (CI workflow) and
06-05 (gitops manifests) add more `.tmpl` files under this package's files/ tree and render them
through the same helper. Getting the embed + Render contract right here (and correcting the RESEARCH
layout so template files live UNDER the package — Go embed cannot use `..`) unblocks both.

Purpose (SCAF-02, part 1): the generated T3 Dockerfile must be a proven, secure build — multi-stage,
`output: 'standalone'`, base image pinned by digest (threat T-06-04), non-root uid 1001, and
HOSTNAME=0.0.0.0 (or Next binds localhost and probes fail).

Output: `internal/templates` with embed + Render, the Dockerfile + health-route templates, and
golden tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| upstream base image (node) → built app image | a rug-pulled/retagged base image would poison every built app |
| template data (slug/port) → rendered file contents | operator-derived values interpolated into generated files |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-04 | Tampering | Dockerfile.t3.tmpl base image | medium | mitigate | Pin node base image by digest (not a floating tag); record the digest as an ARG + comment (RESEARCH ## Security Domain V10) |
| T-06-11 | Elevation of Privilege | container runtime user | medium | mitigate | Runner stage runs as non-root uid 1001 (nextjs) per RESEARCH §1 |
| T-06-12 | Tampering | template rendering (missingkey) | low | mitigate | text/template with Option "missingkey=error" so an unset field fails loudly instead of emitting a malformed file |
</threat_model>
