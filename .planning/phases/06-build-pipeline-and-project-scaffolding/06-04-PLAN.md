<objective>
Author the generated GitHub Actions workflow template — the heart of GITOPS-03 (build+publish a
versioned GHCR image on push) and GITOPS-04 (CI updates the gitops image ref without manual cluster
commands). It is a single two-job workflow: `build` (login → metadata → build-push to
ghcr.io/tkayage/<slug>) and `bump` (needs: build, checkout gitops-homelab, kustomize edit set image,
commit+push main). Validate the rendered output with actionlint and lock it with a golden test.

Purpose: The build→bump ordering is load-bearing (RESEARCH Pitfall 4/5): the bump job must depend on
the build job and reuse the exact short-SHA string, or Argo can try to pull a tag before it exists.
Least-privilege and supply-chain controls live here: `permissions:` minimized to contents:read +
packages:write, the cross-repo push uses a fine-grained PAT scoped to gitops-homelab only
(GITOPS_PUSH_TOKEN, threat T-06-01), tokens never echoed (T-06-02), and every action is pinned to a
full commit SHA (T-06-03).

Output: `files/workflow.deploy.yml.tmpl` + actionlint-validated golden test. This plan does not run a
live Actions build — that needs a real GitHub repo (deferred to Phase 8); Phase 6 proves the workflow
is valid and correctly structured in isolation.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CI runner → GHCR (image push) | GITHUB_TOKEN packages:write present in the runner env |
| CI runner → gitops-homelab (image-ref bump push) | GITOPS_PUSH_TOKEN (fine-grained PAT) crosses into a second repo |
| upstream GitHub Actions → CI execution | third-party action code runs with repo/token access |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Elevation of Privilege | GITOPS_PUSH_TOKEN scope | high | mitigate | Fine-grained PAT scoped to gitops-homelab Contents:write only; stored as a GitHub Actions secret; never used for GHCR reads (RESEARCH §3, Open Q1) |
| T-06-02 | Information Disclosure | token handling in CI logs | high | mitigate | docker/login-action masks the registry token; no `echo`/`run` prints a secret; `permissions:` minimized to contents:read + packages:write |
| T-06-03 | Tampering | third-party GitHub Actions (tag-move) | high | mitigate | Pin actions/checkout + all docker/* to full commit SHAs; document the version in a trailing comment |
| T-06-13 | Denial of Service | build→bump race / two-writer push | medium | mitigate | bump `needs: build`; reuse the exact short SHA; rebase-retry loop on the gitops push (Pitfalls 4/5/6) |
</threat_model>
